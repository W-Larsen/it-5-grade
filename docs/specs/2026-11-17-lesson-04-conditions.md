# Spec: урок 4 «Біт на роздоріжжі» — умови «якщо… то… інакше»

**Дата:** 2026-11-17 · **Статус:** реалізовано; теорія для вчителя (`.docx`) ще не зроблена

Третє заняття блоку «Біт усередині комп'ютера», перше після тижня канікул. Попередній spec: [урок 3](2026-10-27-lesson-03-loops.md).

## Розуміння (підтверджено)

- **Що робимо:** заняття 4 — сайт-презентація на каркасі `shared/deck/`, нові рівні гри «Біт-програміст» з умовами, конспект для вчителя. Теорію для вчителя (.docx) робимо останньою, окремо.
- **Навіщо:** продовжуємо серію про Біта (вибір вчителя замість окремого уроку про ШІ; ШІ — кандидат на урок 5, бо там спиратиметься на умови: «ми писали `якщо` самі, ШІ знаходить їх з прикладів»). Після канікул урок водночас повторює цикли: рівні з умовами працюють лише разом із циклом.
- **Головна думка уроку:** умова — це питання з відповіддю «так/ні». Факти для неї дають датчики, а вирішує процесор: «стрибнути чи ні».
- **Теорія (вибір вчителя — усі чотири інтерактиви):** «iPad вирішує: датчики», «Стрілка на коліях» (умовний стрибок, продовження лічильника з уроку 3), «Біт вгадує число» (так/ні = 1 біт), «Гра, повна «якщо»».
- **Гра:** блок-дужка «якщо» (як блок циклу), дві умови — «тут транзистор?» і «попереду сходинка?» — і «інакше». Поле в рівні одне й незмінне; умова обов'язкова, бо **візерунок нерегулярний, пам'ять тісна, а помилкова дія зупиняє Біта** (вибір вчителя замість «трьох світів»).
- **Не робимо:** процедури; нові команди руху чи плитки; умови з «не»/«і»/«або» в грі (лише в «Для допитливих»); цикл «поки»; зміни поведінки рівнів уроків 2–3; зміни уроку 1.

## Підходи (як зробити умову обов'язковою)

| Підхід | Плюси | Мінуси |
|---|---|---|
| A. «Три світи»: у рівня 2–3 варіанти поля, програма має пройти всі (вкладки «Світ 1 ✓ · Світ 2 ✗») | Чесно показує, навіщо умова; як тести у програмістів | Більше інтерфейсу й рушія; вчитель вважає зайвим |
| Б. Випадкове поле на кожен запуск | Ефектно | Учневі може пощастити; незрозуміло, чому то працює, то ні; рівні важко перевірити |
| **В. Одне поле + тісна пам'ять + помилка зупиняє Біта** ✅ | Звичні рівні, мінімум нового інтерфейсу; перевіряється тим самим пошуком, що в уроці 3 | Треба ретельно підбирати карти, щоб обхід без умови не влазив у пам'ять |

**Вибір вчителя — В.** «Навіщо нам 3 світи? Просто зробимо рівні, куди можна дійти лише з умовами.»

## Припущення (мої рішення, вчитель може виправити)

1. Стиль, керування, звуки, iPad/Safari, `localStorage` лише для зірок (try/catch), без даних учня — як в уроках 2–3.
2. **Суворий режим:** на рівнях з `if` будь-який «стук» (`bump-*`) і «увімкнути» на плитці без транзистора (`no-target`) **зупиняють програму**: Біт каже, що сталося, програма спиняється. На рівнях уроків 2–3 поведінка не змінюється.
3. Умова `transistor` = «на плитці під Бітом є транзистор» (неважливо, увімкнений чи ні). Карти будуємо так, щоб Біт не проходив по транзистору двічі (інакше `увімкнути` його вимкне).
4. Умова `step` = «попереду є плитка іншої висоти» (на неї працює `стрибнути`; сходинка вище ніж на 1 у цих рівнях не трапляється).
5. Блок «якщо» займає 1 комірку пам'яті разом зі своїм «інакше»; кожна команда всередині — 1. Ліміт пам'яті рівнів ≤ 8, як в уроці 3.
6. Вкладеність блоків (цикл і «якщо» разом) ≤ 2: `повтори { якщо { … } }` можна, `повтори { повтори { якщо … } }` — ні. Цикл усередині «якщо» не потрібен жодному рівню, тож пульт його не дозволяє.
7. Перевірка умови — видимий крок: Біт дивиться (під ноги чи вперед), над ним бульбашка «транзистор? ✓ так» / «✗ ні», рядок коду підсвічується. У «⏭ Крок» це окремий крок.
8. Код (моє рішення): `якщо (тут_транзистор()) {` / `якщо (попереду_сходинка()) {` / `} інакше {` / `}`; EN — `if (on_transistor()) {` / `if (step_ahead()) {` / `} else {` / `}`.
9. Машинна команда на слайді «Стрілка на коліях»: `стрибни, якщо…` з кодом **`111`** — останній вільний трибітовий код (001–101 — урок 2, 110 — урок 3). «Усі 8 кодів зайняті!»
10. Числа й поведінка iPad на слайді датчиків спрощені (поріг 20 %, кут повороту ~45°); датчики імітуються повзунками, справжні датчики iPad не читаємо (на iOS вони потребують дозволу).

### «Якщо» у грі

```
┌──────────────────────────────┬──────────────────────────────┐
│                              │ ПАМ'ЯТЬ ▮▮▮▮▮▯▯▯  5/8        │
│     ізометричне поле         │ ┌ 🔁 ×8 ─────────────── ✕ ┐  │
│       з Бітом                │ │ [↑]                      │  │
│        «транзистор? ✓»       │ │ ┌ ❓ [💡 транзистор] ─ ✕ ┐│  │
│                              │ │ │ [💡]  ▏+               ││  │
│                              │ │ ├ інакше ───────────────┤│  │
│                              │ │ │ [↑]                    ││  │
│                              │ │ └────────────────────────┘│  │
│                              │ └──────────── коло 3/8 ────┘  │
│                              │──────────────────────────────│
│                              │ 1 повтори(8) {               │
│                              │ 2     вперед()               │
│                              │ 3     якщо (тут_транзистор()) {  ◀
│                              │ 4         увімкнути()        │
│                              │ 5     }                      │
│                              │ 6 }                     [EN] │
├──────────────────────────────┴──────────────────────────────┤
│ [↑][↶][↷][⤴][💡] [🔁 цикл] [❓ якщо]      │ ▶ Запуск ⏭ Крок ⟲ │
└─────────────────────────────────────────────────────────────┘
```

**Редагування** (як цикл; лише дотики, команди додаються в кінець там, де курсор):
- **❓** у пульті додає блок «якщо» з першою дозволеною умовою; курсор `▏+` переходить у його тіло.
- Тап по чипу умови в шапці — перемикає умову (💡 транзистор ↔ ⬆ сходинка), якщо рівень дозволяє обидві.
- Кнопка «+ інакше» в шапці (на рівнях з `else`) додає нижню частину; курсор — туди. ✕ на «інакше» прибирає лише її.
- Тап у частину блока — курсор туди; ✕ на блоці — прибрати разом із вмістом; `Backspace` — остання команда там, де курсор.

**Виконання:**
- Перевірка умови — окремий крок (припущення 7). Гілка, що виконується, підсвічується; інша тьмяніє.
- Суворий режим (припущення 2): помилка → Біт пояснює («Іскра! Тут немає транзистора», «Там сходинка — треба стрибнути!»), програма спиняється, кнопка ⟲.
- «коло N/M» і спалах «⤴ стрибок назад» — як в уроці 3.

**Зірки й підказка:** як в уроці 3 — за кількістю комірок, `best` = розмір `solution`; підказка після 2 невдач — початок `solution`.

| **Бонус** (4-b1, 4-b2) | пам'ять рівно на оптимум | |

**Правила для кожного рівня з `if` (перевіряє `check-levels.js`):**
1. `solution` проходить рівень у суворому режимі й займає рівно `best` комірок.
2. Пошук найкоротшої програми (з умовами, вкладеність ≤ 2) не знаходить коротшої за `best`.
3. **Без «якщо» не пройти:** найкоротша програма лише з циклами (у суворому режимі) довша за `slots`.
4. У «Нерівних сходах» без «інакше» не пройти в межах `slots`.
5. Запас пам'яті: «Ліхтарі» — `best + 2`, решта — `best + 1`, бонуси — рівно `best`.
6. Біт ніколи не проходить двічі по транзистору в `solution` (припущення 3) і високі блоки не ховають транзистори (`hiddenTargets`, як раніше).

**Формат рівня:**
```js
BitGame.level("4-05", {
  title: "Нерівні сходи",
  map: [...],
  start: { x: 0, y: 0, dir: "E" },
  commands: ["forward", "left", "right", "jump", "light", "repeat", "if"],
  conditions: ["step"],          // які умови дає чип (transistor, step)
  else: true,                    // чи можна додати «інакше»
  nest: 2,
  solution: [{ repeat: 7, body: [{ if: "step", then: ["jump"], else: ["forward"] }] }, "light"],
  slots: 6, best: 5,
  say: "Сходинки різні — треба дивитися!"
});
```

### Технічна архітектура

```
shared/bit-game/engine.js      + елемент { if, then, else? }; condition(lv, st, name);
                                 exec(lv, program) — покрокове виконання (генератор/ітератор кроків),
                                 run() на ньому; суворий режим для рівнів з "if";
                                 size/depth/validateProgram/codeLines/addItem/… знають «якщо»; CODE.if/else/умови
shared/bit-game/bit-game.js    + блок «якщо» (чип умови, «+ інакше», ✕), курсор у then/else,
                                 крок «перевірка» (бульбашка ✓/✗, погляд Біта), підсвітка гілки,
                                 зупинка в суворому режимі; виконання від exec() замість this.steps
shared/bit-game/levels-04.js   4-00, 4-i1, 4-01…09, 4-b1…b2
lesson-04-conditions/          index.html (Deck), teacher-notes.md, потім Урок-4-теорія-для-вчителя.docx
tools/program-search.js        + перебір блоків «якщо» (з «інакше») у тілах; суворий режим
tools/check-levels.js          правила 1–6
tools/*.test.js                тести умов, суворого режиму, пошуку
game/index.html, site/index.html, README   фільтр/набір і картка уроку 4
```

- **Програма:** елемент — рядок-команда, `{ repeat: N, body }` або `{ if: "transistor"|"step", then: [...], else?: [...] }`. Шлях усередину «якщо» має розрізняти `then` і `else` (формат шляху — на розсуд реалізації, напр. `[i, "else", j]`).
- **Виконання:** `exec` видає кроки двох видів: `{ kind: "check", cond, result, path, laps }` і `{ kind: "cmd", cmd, event, state, path, laps, jumps }`. Без «якщо» послідовність команд та сама, що з `expand()` (тест-регресія на всіх рівнях уроків 2–3); `expand()` лишається для старого коду/тестів або замінюється — на розсуд реалізації.
- **Пошук:** стан поля після елемента однозначно визначається станом перед ним, тож пошук по станах з уроку 3 працює й з умовами; у тілах перебираються також блоки «якщо». Помилка в суворому режимі = гілка відсікається.
- На сторінці уроку 4 підключається лише `levels-04.js` (зірки, посвідчення — лише рівні уроку 4).
- Слайди теорії — звичайні інтерактиви в `lesson-04-conditions/index.html` на `shared/deck/`; таймери на `setInterval`, як в уроці 3.

### Тестування

1. `engine.test.js`: умови (`transistor`, `step`), `then`/`else`, «якщо» в циклі, вкладеність, суворий режим (стоп на стуку й `no-target`), `size`/`codeLines` з «якщо»; регресія — усі рівні уроків 2–3 дають ті самі кроки й результат.

4. Фінально — вчитель на iPad у Safari.

### Дрібниці, вирішені під час перевірки spec (мої рішення)

- Порожній блок «якщо» (або порожнє «інакше») — як порожній цикл: «Пуск» спрацьовує, Біт каже «У «якщо» нічого немає».
- Якщо рівень дає лише одну умову, чип у шапці не перемикається (просто підпис).
- «Якщо» можна ставити й поза циклом; цикл усередині «якщо» — ні (припущення 6).
- Умова `step`: попереду край поля → «ні»; сходинка вище ніж на 1 → «так», але `стрибнути` дасть помилку (у рівнях не трапляється).
- Міні-гра слайда 7: кошик рухається пальцем (перетягування) або тапом по лівій/правій половині; на Mac — стрілки.
- Слайд «Біт вгадує число»: межі 1–100, Біт питає «Твоє число більше за N?», N — середина діапазону.
- «Цікаві сайти» для `recap` підбираємо й перевіряємо під час реалізації, як в уроці 3.

## Підсумок реалізації

- **Рушій** (`engine.js`): елемент `{ if, then, else? }`, шляхи з сегментом `"e"`, `condition`, `walk` (замість `expand` у `run` і в компоненті; `expand` лишився для пошуку), суворий режим (`lv.strict` = є `"if"`). Пошук (`program-search.js`): блоки «якщо» лише в тілі зовнішнього циклу, опції `noIf`/`noElse`. `check-levels.js`: правила 1–6 (`checkIfLevel`).
- **Рівні** (`levels-04.js`, усі ✓ в `check-levels`): `4-00` «Квадрат», цикл у циклі (5/5) · `4-i1` (4/6) · Ліхтарі `4-01` (4/6), `4-02` «Поворот» (7/8), `4-03` «Кільце» з новою умовою «край» (6/7) · Нерівні сходи `4-04` (5/6), `4-05` «Сходи по колу» (7/8), `4-06` «Лампи на сходах» (7/8) · Все разом `4-07`, `4-09` (6/7), `4-08` «Кільце зі сходами» (8/8) · бонуси `4-b1`, `4-b2` (6/6). Розв'язки — у `teacher-notes.md`. Приклад формату в цьому spec має `slots: 6, best: 5` (було помилково 5/4).
- **Слайди** (`lesson-04-conditions/index.html`, 14): `back`, `warmup`, `tapgreen`, `sensors`, `rails`, `ifgame`, `guess`, `fun`, `game1`–`game3`, `bonus`, `recap`, `badge`. Бейджів 11.
- **Рішення під час реалізації:** (1) гілка «інакше» стоїть **поруч** з «якщо», а не під ним, щоб блок з циклом уміщався на панелі; для рівнів з `if` панель програми вища (75 %). (2) `4-02` з одним поворотом: відступ пам'яті 1 (best 7, slots 8), бо у 8 комірок «best + 2» не влазить. (3) `4-00` має найкоротший розв'язок `повтори(9){вперед() увімкнути()}` (на звичайному рівні «увімкнути» на порожній плитці нешкідливе), як бонуси уроку 3. (4) У «Біт вгадує число» суперечливих відповідей бути не може (діапазон завжди коректний), тож повідомлення «Ти щось наплутав!» не потрібне. (5) У міні-грі кошик рухається лише вказівником/пальцем: стрілки зарезервовані під навігацію слайдів.
- **Правки після перегляду вчителем (2026-11-17):** (1) додано третю умову `edge` («попереду край»: немає плитки), рівні-кільця повертають самі, рівні стали різними за будовою розв'язку; (2) розминка 4-00 — цикл у циклі (`nest 2`); (3) панель гри для рівнів з `if` ширша (400 замість 300), код крупніший, гілки «то | інакше» стоять поруч і мають підписи, чип умови з ⇄ там, де умов кілька, а де одна — пунктирний підпис; (4) слайд «датчики» й «стрілка» мають явні завдання з галочками, прапорець підписаний «так/ні»; (5) «Біт вгадує число» — від 1 до 1000 (10 питань, 10 бітів); (6) помилка на краю поля лишається фатальною (рівень не прощає зайвого повтору), але Біт підказує «Може, повторів забагато?». Рішення «не прощати край» перевірено: поблажливий режим робить можливими розв'язки з перебором повторів, і `check-levels` перестає гарантувати, що без «якщо» не пройти. Вкладеність «якщо» в «якщо» не додавали: пошук оптимуму її не перебирає.
- **«Цікаві сайти»**: Blockly Games «Лабіринт», Lightbot, Scratch; підписи не містять неперевірених тверджень.
- **Перевірка:** `node --test …` і `node tools/check-levels.js` проходять; у вбудованому браузері 1180×820 пройдені слайди `tapgreen`, `sensors`, `rails`, `ifgame`, `guess`, `fun`, `recap`, `badge`, рівні `4-i1`, `4-04`, `4-07`. Не перевірено: Safari на iPad, інші рівні очима в усіх ракурсах (тест видимості транзисторів зелений).

| Ризик | Що робимо |
